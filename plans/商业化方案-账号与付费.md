# MModels 商业化方案：账号体系 · 付费控制 · 管理后台

> 2026-09-27 初版。基于当前代码现状（Electron 33 + 本地 SQLite + bridge.ts 协议桥 + ProviderConfig baseUrl/apiKey 抽象）设计。

---

## 〇、结论先行（推荐路线）

**一句话：自建轻量服务端（Hono + PostgreSQL，国内云/香港云）+ 桌面端账号门禁 + AI 调用全量收归服务端中转（核心付费锚点）+ 卡密兑换起步支付 + Web 管理后台。**

三条铁律：

1. **付费锚点必须放在服务端**——AI 能力（DeepSeek 中转）全部经过你的服务器计费校验，未付费 = 无法调用。这是唯一防得住破解的控制点；纯本地功能只能"软控制"（防君子）。
2. **客户端校验做缓存不做裁决**——桌面端定期向服务端核实账号状态，离线给 72h 宽限期，到期本地降级。
3. **分期上线，先跑通闭环再补支付**——Phase 1 账号+门禁+AI 中转（核心），Phase 2 管理后台，Phase 3 卡密商城，Phase 4 增强功能。

- **个人账号**：邮箱 + 密码注册（起步零门槛，QQ 邮箱学生普及）；后续加手机号验证码、微信扫码。

## 三、系统架构

```
┌─ 官网（现有 GitHub Pages）─── 下载 / 购买入口 / 卡密说明
│
├─ 云服务器（一台 2C4G 起步）
│   ├─ API 服务（Hono + TypeScript，与主项目同栈）
│   │   ├─ /auth      注册 / 登录 / 验证码 / 刷新 token
│   │   ├─ /license   状态校验 / 设备绑定 / 心跳
│   │   ├─ /ai/v1     ★ AI 中转（校验→配额→转发 DeepSeek→计量）
│   │   ├─ /redeem    卡密核销
│   │   └─ /admin/*   管理接口（管理员角色）
│   ├─ 管理后台（React SPA，/admin 路径，管理员登录）
│   ├─ PostgreSQL（用户/订单/卡密/用量/审计）
│   └─ Caddy/Nginx（HTTPS + 反代）
│
└─ 桌面端（现有 Electron 应用改造）
    ├─ 启动门禁：未登录 → 登录窗（内置 WebView 或原生表单）
    ├─ 账号状态机：ok / grace(离线宽限) / expired / banned
    ├─ 设置页新增「账号」分区：当前套餐/到期/用量/设备管理
    └─ AI 调用：内置 provider → https://api.你的域名/v1（账号 token 鉴权）
```

### 3.1 ★ 核心付费锚点：AI 中转（为什么必须做）

- 现状 DeepSeek key 在客户端/用户手里 → 无法计费、无法控制。
- 改造后：所有 AI 请求带账号 token 打到你的服务器 → 服务端校验（登录态、套餐、功能位、当日配额）→ 用你的 DeepSeek key 转发 → 流式返回，同时按响应 usage 记账。
- **破解客户端也没用**：没有有效账号 token，AI 一律 403。数模产品的核心价值（多智能体跑全流程）依赖 AI，锚点成立。
- 保留「自定义 API Key」高级选项（用户自带 key 走直连）作为规避项？**建议保留但仅限年卡/VIP**——既尊重高级用户，又保护基本盘。
- 中转服务端可直接移植 `bridge.ts` 的协议状态机（TS 同栈），或更简单：中转层只做「校验 + 计量 + 透传」，协议转换仍留在客户端（客户端本来就会说 OpenAI 协议，服务端透传给 DeepSeek 即可）。**推荐透传方案**，服务端复杂度最低。

### 3.2 客户端校验机制

- **启动**：读本地缓存凭证（safeStorage 加密）→ 有则静默 `POST /license/check`（带 token + 设备指纹）→ 按返回状态进入 ok/grace/expired/banned。
- **心跳**：每 6 小时后台静默校验一次；登录态变更（升级 VIP、封禁）即时生效。
- **离线宽限**：最近一次校验成功后 72h 内可离线使用（比赛现场网络差的真实场景）；超 72h 锁定，联网恢复。
- **防时间作弊**：一切到期判断以服务端时间为准；检测到本地系统时间早于上次心跳（倒拨）→ 强制联网校验。
- **设备绑定**：一账号限 2-3 台设备（设备指纹 = machine-id hash）；超限在管理后台/客户端「设备管理」里自助解绑（每周 1 次）。
- **降级体验**：expired ≠ 不能开软件——软件可开、可看历史项目，AI 与 VIP 功能置灰 + 引导续费（比直接锁死体验好、转化高）。

### 3.3 数据库核心表（PostgreSQL）

```
users        id, email, password_hash, nickname, role(user/admin),
             status(active/banned), created_at
devices      id, user_id, fingerprint, name, last_seen, revoked
plans        id, code, name, duration_days, ai_daily_quota, features_bitmap, price
entitlements user_id, plan_id, expires_at, features_override  ← VIP 开关落点
redeem_codes code, plan_id, batch, status(unused/used), used_by, used_at
ai_usage     id, user_id, day, model, prompt_tokens, completion_tokens, cost
orders       id, user_id, type(redeem/manual), plan_id, created_at, note
audit_log    admin 操作审计（谁在何时改了谁的 VIP/时长）
```

## 四、支付方案（国内个人开发者现实约束）

| 方案 | 资质要求 | 手续费 | 结论 |
|---|---|---|---|
| **卡密/兑换码（推荐起步）** | 无 | 平台发卡渠道约 1-5% | ✅ Phase 3 先行：淘宝/微店/闲鱼发卡 → 客户端输码激活。数模软件市场本就以淘宝发卡为主流，零资质门槛 |
| 虎皮椒 / Xorpay 聚合 | 个人可申请 | 2-3% | ✅ Phase 4：官网在线支付（微信/支付宝扫码），免企业资质 |
| 官方微信支付/支付宝商户 | 企业资质 | 0.6% | ⏳ 有资质后切换 |

卡密闭环：后台批量生成卡密（按套餐/批次）→ 发卡渠道售卖 → 用户客户端「兑换」输入 → 服务端核销 → 写 entitlements。全程不需要支付接口，商业闭环成立。

## 五、管理后台功能清单

1. **数据看板**：注册数/日活/付费转化/当日 AI 成本（DeepSeek 花费 vs 收入）
2. **用户管理**：搜索、查看详情（套餐/到期/设备/AI 用量曲线）、手动调整时长、VIP 功能位开关、封禁/解封
3. **卡密管理**：批量生成（选套餐+数量+备注批次）、导出、查询状态、作废
4. **套餐管理**：价格/时长/配额/功能位编辑
5. **AI 用量**：按用户/按天/按模型统计，异常用量告警（刷量检测）
6. **审计日志**：所有管理员操作留痕
7. **公告系统**：客户端内公告（维护通知、新版推送）

技术栈：React + Vite 独立 SPA（复用主项目组件风格），同源部署 `admin.你的域名`，管理员账号独立强密码 + 登录失败锁定。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 纯本地功能被破解 | 接受（防君子）。核心 AI 锚点在服务端，破解者拿不到免费 AI |
| token 被提取共享 | 设备指纹绑定 + 异常并发检测（同 token 多设备同时在线告警/踢下线） |
| AI 刷量/滥用 | 每日配额（套餐位定义）+ 用量曲线异常告警 + 单请求 token 上限 |
| 服务器被打/挂 | 心跳失败进离线宽限期，用户无感；AI 中转不可用 → 客户端明确提示而非卡死 |
| DeepSeek key 泄露（服务端） | key 只存服务端环境变量，永不下发客户端 |
| 学生付费意愿 | 免费试用 + 单次赛卡低门槛 + 战队卡分摊成本 |
| 邮箱验证码到达率 | 起步用 QQ/163 邮箱可收的 SMTP 服务；后期加手机号 |

## 九、需要你拍板的 3 个决策点

1. **AI 中转模式**：推荐「全量中转 + VIP 保留自定义 Key」；另一选项是「强制全量中转」（控制力最强但高级用户可能不满）。
2. **服务器节点**：香港（免备案、今天就能上线）vs 国内（备案 2-3 周后上线，延迟更好）。**建议先香港跑通 Phase 1，同步备案。**
3. **起步支付**：确认「卡密先行」（Phase 3），还是想一步到位接在线支付（需先确认虎皮椒类渠道的可用性）。
