## 三、坑清单（⚠️ 每条都实测踩过，接手必读）

1. **bytenode 必须用 `compileFile` 高层 API，禁止裸调 `compileElectronMainCode/compileElectronRendererCode`**。
   裸调产出「裸 vm.Script(code)」字节码（没包 CJS wrapper），加载端 `Module._extensions['.jsc']` apply 时抛 `ReferenceError: module is not defined` → main 捕获后 showErrorBox 模态卡死。
   `compileFile` 内部 `Module.wrap(code)` 包 wrapper，且 `createLoader: 'commonjs'` + `loaderFilename` 直接生成 stub 覆盖原 .cjs。
   ```js
   await bytenode.compileFile({
     filename: cjsFile, output: jscFile, electronPath: ELECTRON_EXE,
     electronRenderer: true,        // preload 用（renderer 进程加载）
     // 或 electronMain: true,      // security 用（main 进程加载）
     createLoader: 'commonjs', loaderFilename: path.basename(cjsFile),
   });
   ```

2. **字节码编译上下文不能搞混**：preload 必须用 `electronRenderer: true`（renderer 的 read-only snapshot），security 必须用 `electronMain: true`（真 main 进程，**不是** ELECTRON_RUN_AS_NODE——Electron ≥42 用 run_as_node 编译的字节码加载时 SIGTRAP）。混用会 cachedDataRejected 或崩溃。bytenode 1.7.0。

3. **harden.cjs 有防重入检查**：在已加固产物上重跑会把 stub 当源码二次字节码化（真实 preload 逻辑丢失，index.jsc 缩水到 10KB）+ 混淆叠加（main 膨胀到 10MB）。重跑前必须先 `electron-vite build` 覆盖 out/。

4. **`FuseVersion` 的键是大写 `V1`**（@electron/fuses 2.1.3）。写 `v1` 得 undefined → flipFuses 抛 `Unsupported fuse version number: undefined`。

5. **反篡改拒绝启动必须「静默落盘后 process.exit(1)」，禁用 showErrorBox+app.exit**——showErrorBox 是模态的，阻塞事件循环，`app.exit(1)` 永远执行不到，进程表现为「卡住活着」（T3 最初 FAIL 就是这个）。

6. **Chromium switch 不在 `process.argv`**：`--remote-debugging-port` 被 Electron 从 argv 剥离，检测必须用 `app.commandLine.hasSwitch('remote-debugging-port')`。argv 检测只对 `--inspect` 类 Node 参数有效。

7. **单实例锁按 userData 算**：`app.setName('MModels')` 后 dev/测试实例与用户开着的正式版共用 `%APPDATA%/MModels` → 抢锁失败静默退出（零输出零进程）。已加 `MATHMODEL_USERDATA` 环境变量开关（src/main/index.ts，setName 之后）。测试脚本必须设它。

8. **E2E 的 `--user-data-dir` 是 Chromium switch，对 Electron 的 `app.getPath('userData')` 无效**——test-real-app.cjs 以为隔离了其实没有。它已设 `MATHMODEL_E2E=1`（anti-tamper 豁免 + 项目落 userData），但锁隔离要靠 `MATHMODEL_USERDATA`（待加）。

9. **所有构建/打包/起 Electron 必须过 `scripts/clean-env.cjs`**（项目铁律，防宿主 NODE_OPTIONS/ELECTRON_RUN_AS_NODE 注入假故障）。shell:true 坑：cmd.exe 不认 `./x.exe` 路径形式。

10. **混淆对 ESM 的雷**：`renameGlobals: false`（external 引用风险）；混淆器对 `import.meta` 保留原样 OK。当前强度（flatten 0.5 / deadCode 0.3 / selfDefending）实测启动 3s 正常，性能如需再调低阈值。

## 七、设计定位（诚实边界）

客户端四层防线全部是「提高逆向成本」：
- 混淆 + 字节码：AI 无法从字节码还原源码（无训练语料），混淆 JS 对 AI 的去混淆能力也构成实质消耗；
- fuses：官方二进制级运行时锁，杜绝注入类低门槛攻击；
- **绝对防线在服务端**：付费锚点是 AI 调用中转（见 `plans/商业化方案-账号与付费.md` §3.1），破解客户端拿不到免费 AI。本任务的客户端加固与之互补，不追求「绝对不可逆向」（技术上不存在）。

## 八、0.1.16 最终交付状态

### 8.1 安全链路

1. `npm run release:hardened` 先通过 `scripts/clean-env.cjs` 清理宿主注入，再执行正常构建、混淆和安全模块字节码编译。
2. `after-pack` 为安装版和便携版写入相同的 Electron Fuses、`integrity.meta` 和 `license-policy.json`。
3. 启动最早期由 `_security.jsc` 检查环境注入、调试开关、`app.asar` 和关键资源指纹；失败时写入 `startup-error.log` 并立即退出，不留下“假运行”进程。
4. `scripts/.atk-verify.cjs` 在发布流程中自动执行 T1/T2/T3 攻击面回归；`scripts/.pack-verify.cjs` 检查正常启动；`scripts/test-real-app.cjs` 检查真实 SQLite、技能、模板、算法、环境、draw.io、项目文件、终端和自动化功能。

### 8.2 在线授权模式

默认构建 `MM_LICENSE_REQUIRED` 未开启，保证当前本地 API 用户的行为和功能完全不变。商业发布时使用：

```powershell
$env:MM_LICENSE_REQUIRED = '1'
$env:MM_LICENSE_URL = 'https://你的授权服务.example.com/v1/check'
npm run release:hardened
```

商业包只携带策略和服务地址，不把令牌写进安装包。令牌放在用户数据目录的 `license.token`，模型回合开始前向授权服务确认，结果只在内存缓存 1～15 分钟。授权服务应绑定设备、版本、到期时间和撤销状态；不要把“永久有效”写进客户端。

> 诚实边界：只要模型密钥和完整模型调用都在客户端，技术上不存在“绝对不可破解”的纯本地方案。要阻止复制后永久离线使用，必须让商业模型调用经过服务端授权/计费网关；本闸门是客户端配合层，不应替代服务端校验。

### 8.3 升级与兼容

- 业务代码继续按普通开发流程修改；每次发布只运行一条 `npm run release:hardened`，不手工改 `out/`。
- 加固脚本有防重入检查：必须从新的 `electron-vite build` 产物开始，避免重复混淆导致功能损坏。
- 安装版和便携版共用同一个 `out/` 加固产物、同一套测试和同一份发布清单；后续新增资源若会影响运行逻辑，应加入 `scripts/after-pack.cjs` 的关键资源收集规则。
- `dist/release-manifest.json` 保存版本、每个 exe 的大小和 SHA-256，可作为升级服务器的发布索引。
- 当前构建日志显示没有配置 Authenticode 证书（`no signing info identified`）。正式对外发布应配置 `CSC_LINK` / `CSC_KEY_PASSWORD` 或等价签名方案，以便 Windows SmartScreen 和更新器验证来源；这不会改变业务功能。
