## 一、总体评价

**项目健康度：优。** 5.3 万行渲染层 + 2.7 万行主进程 + 48 个内置技能，全量测试 1035/1035、typecheck 零错、全仓零真实 TODO。与历史资料 的对齐已覆盖对话主流程、比赛工作台、竞赛日历、论文库、图表库、数据页、自动化、扩展市场、19 分区设置、桌面小模、协作服务、局域网发现等全部大面。

**三个最值得马上做的方向**（详见第七节路线图）：

1. **技能"求解链"断线**——48 个技能里约 24 个是孤儿（从未被主流程引用），建模求解主线（审题→选型→假设→代码→稳健性）完全游离在 write-paper 之外；
2. **竞赛期刚需技能缺失**——摘要写作、时间规划、规则校验、答辩 PPT 四个直接决定提交成败的环节为零；
3. **图表与代码呈现短板**——DataChartStudio 名不副实（只有 25 行壳）、代码块无语法高亮、图表无导出，与"数学建模工作台"定位差距最大的一块。

## 四、技能体系审查（48 个）

### 4.1 覆盖图与孤儿

| 功能域 | 技能 | 状态 |
|---|---|---|
| 选题审题 | problem-parser、problem-classifier、method-selector、novelty-assessment | **前两个是孤儿** |
| 建模 | model-assumptions-builder、modeling-algorithms、metaheuristic-optimization、symbol-table-builder、modeler-decision-logger | **4/5 孤儿** |
| 求解 | python-model-code-generator、robustness-checker | **全孤儿** |
| 数据 | data-search、data-auditor-cleaner | data-search 主入口；**cleaner 孤儿** |
| 文献 | literature-search/review/positioning、paper-search、related-paper-analyzer | 基本接入；**analyzer 孤儿** |
| 论文 | write-paper（主入口，引 6 技能）、paper-writing/section-writer/polisher | writing 孤儿 |
| 图表 | draw-figures（路由）、nature-figure、mathmodel-figure-templates、paper-diagram | **4 个备用绘图技能全孤儿**，scipilot 与 nature-figure 高度重叠 |
| 审校 | review-paper（主入口）、audit 四件套、latex/table/page-fit、QA、competition-audit | **audit 四件套与 QA 孤儿** |
| 工具 | pdf、doctor、paper-sharing、skill-creator | 用户直呼入口，孤儿可接受 |

**核心发现：主流程 `write-paper` 没有引导用户走"审题→选型→假设→代码→稳健性"这条链**——建模阶段靠 AskUserQuestion 裸问模型选择，而 problem-parser/method-selector/modeling-algorithms 这套现成的"选型链"技能从未被接线。**修复成本极低（改 write-paper 的 SKILL.md 工作流即可），收益却是端到端主流程质变。**

## 五、UI/UX 审查

### 5.1 短板（按影响排序）

1. **长对话无虚拟滚动**（ChatPage.tsx:1380 全量 map）——百条消息 + 流式重渲染会卡；
2. **图表页只能看**——无 echarts 交互绘图、无 PNG/SVG/剪贴板导出（toPng 全仓 0 命中）；
3. **代码块无语法高亮**——Markdown.tsx 无 hljs/shiki，建模产物大量 Python/LaTeX 纯文本渲染；
4. **快捷键无全局注册**——main 侧 globalShortcut 0 命中，应用后台时 mod+k 等全部失效；
5. **皮肤与内容不联动**——mermaid/代码高亮色板固定，换主题后图表色调脱节；
6. 可访问性广度尚可（aria 196 处）但无焦点陷阱（modal 可 Tab 出界）；
7. 小模快捷动作弱（右键菜单只有换装/安静/隐藏）。

## 六、架构与新功能机会（主进程）

### 6.1 Agent SDK 能力利用率

**已充分使用**：query 多轮队列、canUseTool、hooks×6、后台 subagent×7、MCP（内置 15+16 工具）、resume、effort/thinking、autoCompact 窗口。

**未使用（现成机会）**：
- **Plan 模式（B2）**：RunOptions 已预留 interactionMode（session.ts:159）、'plan' 映射已支持（permissions.ts:132），只差 IPC 传值 + canUseTool 插 ExitPlanMode 捕获（session.ts:474 注释已写明插入点）——**半成品收尾即可上线**；
- **SDK checkpoint/fork**：HTTP 端已有自研 revert/fork（server/routes.ts:309/395），换 SDK rewindFiles/forkSession 可获得与对话状态一致的时间旅行；
- **本地 HTTP API 自我暴露**：把 `http://127.0.0.1:<port>/api/...` 写进 workspaceInstructions，agent 可直接 curl 查会话/导出，省大量扫盘 token。

### 6.2 高价值新功能

1. **自动化升级为"赛期编排"**：现在只能整点跑 prompt（automation.ts:321）；复用 7 个后台角色 + orchestration-policy 阶段门，可做"每晚自动跑一轮 review-paper 核验并写 review.md"的比赛周期任务；
2. **bridge 工具块增量流式**：bridge.ts:467-481 目前工具调用参数全量缓冲到 finish 才发，改按 chunk 发 input_json_delta 可让长工具调用有进度感；
3. **xlsx 解析**：DatabasePage 降级点（:31）补后端解析 IPC（xlsx/exceljs），数据页完整度上一个台阶；
4. **Workbench 多 PDF 交付检查**（WorkbenchPage.tsx:63 只扫 pdfPaths[0]）；
5. **协作模块**：collab/server.ts（1482 行，含 UDP 发现/加入码/审批/Agent 转发）成熟度已高但按你的决策两度推迟——建议保持封存，等赛期真实三人协作需求出现再启用（Yjs 替换自研 diff 的建议届时一并考虑）。
