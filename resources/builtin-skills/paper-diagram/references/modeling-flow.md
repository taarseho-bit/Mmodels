# 数学建模证据流程模板

这组模板用于论文正文、答辩汇报和工作流演示，重点是说明“问题怎样被解决”，不是展示课题申请书式的宏大路线。

## 选哪个版式

| 模板 | 适用场景 | 主线 |
|---|---|---|
| `problem-flow` | 一张图概览整篇建模过程 | 题目 → 数据 → 假设 → 模型 → 求解 → 检验 → 结论 |
| `model-architecture` | 解释变量、目标函数和约束怎样组成模型 | 输入 → 变量 → 目标/约束 → 输出 → 检验 |
| `optimization-decision` | 优化、资源配置、路径规划和多情景决策 | 场景 → 决策变量 → 目标 → 求解 → 比较 → 推荐 |
| `validation-loop` | 强调结果可信度和模型修正 | 数据 → 基线 → 运行 → 误差 → 稳健性 → 证据 |

## 内容纪律

- 每个框只放一句“做了什么”和一句“拿什么证据”，不塞大段论文正文。
- 实线表示已经完成的主流程；虚线只表示检验失败后的回修，不表示并行任务。
- `model-architecture` 里的目标函数、约束和边界必须来自当前题目，不能用通用占位词直接交付。
- `validation-loop` 至少写清一种基线、一种误差或残差检查，以及一种敏感性/交叉验证证据。
- 如果一个分问需要不同模型，分别画小图或使用 `problem-flow` 的分支，不要把所有模型横向堆在一张图上。

## 证据对应

图中的每个框都应能指向一个真实产物：题意解析、数据报告、假设清单、模型公式、求解脚本、验证报告、结果图表或论文段落。没有产物支撑的框应删除或标为“待确认”。
