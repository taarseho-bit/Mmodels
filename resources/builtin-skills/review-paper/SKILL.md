# 数学建模论文评审

本版增强：如果用户同时提供比赛工作台中的候选方案或结论证据簿，核对它们与论文、代码和结果是否一致；人工勾选不是验证通过。评语区分“实际复算”“静态检查”“未取得证据”，不要仅凭模型名称、方法复杂度或图表数量判断论文优劣。没有最终 PDF 或当届规则时，对页数与提交合规项标记待确认；不缩减下面的完整评审流程。

产物是当前项目根目录下的 `review.md`。评审对象优先级：用户指定的文件 → 项目里的 `document.tex` →
项目里的 PDF。什么都找不到时问用户要论文，不要凭空评。

## 1. 读全文

- `.tex`：读主文件并顺着 `\input` / `\include` 读完所有章节，看 `book.bib` 与 `figures/`。
- PDF：优先运行本技能的 `scripts/prepare_pdf_review.py <PDF路径>`（Windows 用 `py -3`，macOS/Linux 用
  `python3` 启动脚本）。它会把 PDF 一次性提取成按页文本，
  并返回 `manifest.json`；先按 `pages[].textPath` 读完全文，不要反复直接读取整份 PDF。
- 视觉检查采用“按需转图”，不要默认把几十页全部转成高清图片：先查看 manifest 的
  `suggestedVisualPages`，结合正文里的图表页码，运行
  `scripts/prepare_pdf_review.py <PDF路径> --render 1,2,5-8`。至少看封面、摘要、含图表的页面、
  文字提取很少的页面和排版可疑页。图片按 110 DPI 生成并缓存，已经生成的页面会直接复用。
- 若脚本提示缺少文字读取工具，再退回直接读取 PDF；不要为了评审临时安装依赖。
- 扫描版 PDF 没有可提取文字时，改为分批查看页面图片，每批 6–10 页，避免一次塞入全部页面。
- 记下页数、图表数量、参考文献条数、附录代码是否存在——这些是格式项的硬指标。

对用户只用简短中文说明当前阶段，例如“正在读论文正文”“正在核对图表与结论”。不要展示转换命令、
缓存目录、工具名或大段执行日志；可恢复的读取失败只说“这一页没读清，正在换一种方式”。

## 2. 六个维度打分（每项 0–10，附一句评语）

| 维度 | 评委真正看的点 |
|---|---|
| 摘要 | 是否在半页内讲清：问题是什么、用了什么模型、得到什么数值结果、有什么创新；有没有空话 |
| 问题分析与假设 | 假设是否必要、合理、被后文用到；符号表是否完整；有没有为凑模型硬加的假设 |
| 模型建立与求解 | 模型是否对应题目要求；推导有没有跳步或错误；求解方法是否说明、能否复现；各问是否都作答 |
| 结果与可信度 | 数值结果是否给出、量级是否合理；是否做了灵敏度 / 误差 / 稳定性分析；结论是否回应了题目 |
| 图表 | 图是否说明问题（不是装饰）；图注、坐标轴、单位、图例是否齐全；是否被正文引用；有无重复图 |
| 格式与规范 | 页数是否超限；章节结构是否完整（问题重述→分析→假设→模型→求解→检验→评价→参考文献→附录）；参考文献是否真实且格式一致；代码附录是否可读 |

打分之外，单独列出 **致命项**（任一命中直接拉低档次）：某一问没答、结果明显错误或不给数值、
参考文献疑似编造、页数严重超限、摘要没有具体结果。

## 3. 写 review.md

```markdown
# 论文评审

**总评**：一句话定档（优秀 / 良好 / 及格 / 需要重做）+ 最值得先改的一件事。

## 评分
| 维度 | 分数 | 评语 |
| --- | --- | --- |
| 摘要 | 6/10 | … |
| … | … | … |
| **合计** | **xx/60** | |

## 致命项
- （没有就写"无"）

## 问题清单（按对得分的影响排序）
1. **[维度] 问题一句话** — 位置（章节 / 页码 / 图号）
   - 现状：…
   - 改法：…（具体到怎么写、补什么数据、换什么图）
2. …

## 可选加分项
- …
```

要求：
- 每条问题必须给**位置**和**改法**，不接受"建议加强论证"这类空评语。
- 引用论文原文时用短引，不要大段复制。
- 判断参考文献真实性时，可调用 `paper-search` skill 核验可疑条目；核不到的标为"疑似编造"而不是直接下结论。

## 4. 收尾

在对话里给出总评、合计分与前 3 条问题，附 `review.md` 路径，然后问一句：
**"要我按问题清单第 1–N 条直接修改论文吗？"** 用户确认之前不动 `document.tex`。
用户确认后，改动按 `write-paper` 的写作规范执行，并在 `review.md` 末尾追加"已修改"记录。

## 评审透明化

- **开工宣言**：先说明评审范围（读哪些文件、按什么标准打分），再开始逐项审。
- **分维度评分**：模型正确性 / 假设合理性 / 结果验证 / 图表表达 / 写作规范 各给分项与理由，汇总成总分与等级。
- **问题分级**：每条意见标严重程度（阻断 / 建议 / 打磨），给位置（章节/页码/公式号）与可执行的修改动作。
- **核真优先**：引用逐条核真、数值抽查复算；发现编造直接标红，不含糊。
