# 摘要页写作（评分权重最高的一页）

摘要不是压缩全文，而是**替评委 10 分钟内建立"值得细读"的预期**。评审普遍先读摘要定档，再翻正文验证——摘要缺数值结果、模型说不清、亮点不突出，任何一条都可能直接掉档。

## 从结果出发，不从动机出发

动笔前先读齐三类材料，**缺一类就先停下来向用户要，不要凭印象编数字**：

1. `solve/` 下的求解产物：每问模型说明、关键参数、核心数值结果（最优值/预测值/误差/排名）。
2. 论文 `.tex` 正文：每问建模章节的结论段与"模型检验"小节（灵敏度/稳健性数据）。
3. `book.bib` / 图表清单：确认摘要点名的方法与图表在正文真实存在。

没有任何数值结果时（模型还没跑完），如实告知用户"摘要暂时只能写到方法层"，并先产出**带占位符**的版本（`\result{...}` 标记），跑完再回填——禁止编造"满意的结果表明模型有效"这类空话。

## 结构模板（逐问展开，一问一段）

```
第一段（开头）：
  用一两句话复述题目要求解什么，给出总体建模思路（用了哪几类模型、
  按什么主线串起来）。不抄题面，写"我们把它转化为什么问题"。

中间段（每问一段，问与问之间体现递进关系）：
  针对问题一，建立××模型：先××（处理手段，如无量纲化/插值/拟合），
  再通过××（算法/方程）求解，得到××（关键数值结果：最优值、误差、
  排名、变化区间）。结果说明××（一句话结论，与前问衔接）。
  ——每段必须至少有一个具体数字；没有数字的段落评委默认"没算出来"。

检验段：
  用××方法做灵敏度分析：关键参数变动 ±x% 时结果变动 y%，表明模型
  对××不敏感/稳健。（有就写，没有就先去跑 robustness-checker）

结尾段（亮点）：
  本文的亮点是××（模型创新点/数据处理亮点/验证严谨性），2-3 条，
  每条一句话，不夸大。
```

## 写作纪律（评审视角的硬约束）

- **第三人称或无主语**，不用"我/我们觉得"（国赛传统可用"本文"）。
- **不用公式推导**，公式只在必要处点名模型名（如"建立整数规划模型"），不放 LaTeX 长式。
- **不出现图表编号**（"如图 3 所示"是摘要大忌），引用结果直接给数字。
- **关键词 3-5 个**放在摘要末尾：模型名 + 核心方法 + 对象，不写"MATLAB"这类工具名。
- 每问一段之间**显式衔接**（"在此基础上""为解决问题二中的××"），避免四段互不相干。
- 长度：国赛中文摘要 300-500 字/页一页内；美赛 Summary Sheet 一页内（含一小图可选）。

## 美赛（MCM/ICM）附加要求

- 英文 Summary Sheet 单独一页：段落结构同上，另加一行 **Bibliography 可省**（正文给即可）。
- 数字与单位用英文习惯（thousand separators、units 斜体规则由模板管）。
- 中式英语自查：删掉"according to the problem, we can know that"这类模板腔；
  "our model demonstrates robustness"优于"the model is very good"。

## 自检清单（产出前逐项核对，任何一项不过就改）

1. 每问都有至少一个具体数值结果，且**与正文/表格完全一致**（回读 `solve/` 产物核对，不要凭记忆转写）。
2. 每问都点明了模型名称与求解方法（评委会找关键词）。
3. 有灵敏度/检验结论（哪怕一句）。
4. 无图表编号、无长公式、无第一人称、无空洞形容词（"很好、非常、极大提高"）。
5. 结构：开头总起 + 逐问分段 + 检验 + 亮点收尾，段间有衔接。
6. 美赛版无中式英语、时态统一（一般现在时为主）。

## 产出

- `abstract-draft.md`：中文稿（含逐问草稿与自检结果表）。
- 美赛项目另出 `summary-sheet.tex` 片段，直接可粘进模板的 summary 环境。
- 若用户已有摘要：先按上述清单逐项体检、输出"改前/改后 + 每处修改理由"，经确认再替换 `.tex` 中的摘要环境。
