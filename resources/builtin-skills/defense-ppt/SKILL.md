# 答辩准备（从论文到讲稿）

答辩的本质是**用 10-15 分钟把评委没读过的论文讲成一个可信的故事**：问题难在哪 → 我们怎么建模 → 结果是否可信 → 亮点是什么。评委提问 80% 集中在模型假设、方法选型理由、结果验证三处。

## 第一步：抽取素材（只读）

读齐论文 `.tex`、`solve/` 求解产物、`book.bib`、图表源文件，整理：

1. 每问的：模型名、方法链、核心数值结果、灵敏度结论。
2. 图表清单：标注哪些是"答辩级"图（技术路线图、主结果图、灵敏度对比图），哪些只留在论文。
3. 假设清单：`solve/01-assumptions.md`（若做过 model-assumptions-builder）——这是评委提问的弹药库。

论文未完成或结果缺失时如实告知：先补论文再准备答辩，脚本里对应页标"待补"。

## 第二步：答辩大纲（15 分钟标准版，落盘 `defense/outline.md`）

| 页 | 时长 | 内容 | 素材 |
|---|---|---|---|
| 1-2 | 1min | 题目一句话 + 总体技术路线（用 paper-diagram 的技术路线图） | roadmap 图 |
| 3-5 | 4min | 问题一：建模思路 → 方法 → 关键结果（一个主图 + 一个数值表） | |
| 6-8 | 5min | 问题二三：同构展开，突出与前问的递进 | |
| 9 | 2min | 模型检验：灵敏度/稳健性/误差对比（评委最看重的页） | robustness 图 |
| 10 | 2min | 亮点与创新：2-3 条，每条一句"我们做了什么不同的" | |
| 11 | 1min | 局限与改进（主动说局限反而加分，评委必问） | |

逐页脚本要求：每页写"标题 + 3 条要点 + 讲稿（口语化，每页 ≤150 字）+ 该页放哪张图（给出文件路径）"。总页数 ≤12 页——超了先删过程页，不是压缩字号。

## 第三步：预设评委问答（落盘 `defense/qa.md`）

按三类各准备 3-5 问，每问写"问题 + 30 秒标准答案 + 证据出处（论文哪一节/哪个文件）"：

1. **假设类**："假设 ×× 是否合理？如果 ×× 不成立会怎样？"——答案挂接到假设的失效信号。
2. **方法类**："为什么选 ×× 而不用 ××？"——答案回指 method-selector 的备选与对比。
3. **结果类**："这个结果怎么验证？对参数敏感吗？"——答案回指 robustness-checker 的数据；**答不上数值等于没验证**。

另准备 2 个"陷阱题"（自己论文最薄弱处，评委大概率会打的点）及应对话术。

## 第四步：模拟答辩

用户要求演练时：按 qa.md 随机提问，用户作答后给评分与改进点（回答是否落在证据上、是否超 30 秒）。每轮结束更新 qa.md 的"演练次数"与"答得最弱的三个问题"。

## 产出

- `defense/outline.md`：逐页脚本 + 素材清单（每页标注图表文件路径，可直接交给做 PPT 的队友）。
- `defense/qa.md`：预设问答 + 演练记录。
- 不产出 .pptx：页脚本 + 素材路径足够任何模板快速成稿；需要时提示用户可用 `paper-diagram` 的路线图作为第 2 页主视觉。
