# 数学建模论文全流程

这是项目级的论文生产流程。先把问题算清楚，再写正文；不能用润色掩盖模型、数据或结果问题。

## 1. 读取项目资料

先读取当前项目的 `.mathmodel/paper/config.json`（如果存在），确认比赛、年份、题号、模板来源和页数要求。读取题目 PDF、数据文件、已有代码、结果和论文源文件，列出实际存在的资料；不要凭文件名猜测内容。

当模板入口文件不存在时，才把模板复制到项目中；已有论文、配置、代码和人工修改不得被模板覆盖。

## 2. 先完成建模，再写作

按每个子问题单独建立工作卡，至少包含：

- 目标、决策变量、状态量和单位；
- 已知条件、约束、边界和终止条件；
- 评价、预测、优化或机理分析的题型判断；
- 主方案、简单基线和备选方案；
- 可行性检查、目标值复算、约束残差和独立交叉验证方式。

优先调用以下技能并保留产物：

1. `problem-parser`
2. `problem-classifier`
3. `method-selector`
4. `model-assumptions-builder`
5. `model-selection-audit`
6. `baseline-comparison`
7. `python-model-code-generator`
8. `robustness-checker`
9. `result-reproducibility`

如果某项技能没有启用，完成同等检查并写出同名或近似的项目记录，不要静默跳过。

每个问题单独保存求解脚本和结果，脚本必须输出求解状态、目标值、关键残差、基线对比和主要参数。启发式算法不得把单次最好结果直接称为全局最优；非凸问题至少用多个初值或不同方法复核。

## 3. 生成图表和示意图

图表先服务于结论，再考虑装饰。数据图使用 `scientific-figure-making`、`figure-table-planner` 或 `mathmodel-figure-templates`；问题求解流程、模型结构、优化决策和验证闭环使用 `paper-diagram`。

所有图表应：

- 使用当前项目真实数据；
- 统一中文字体、配色、字号和 DPI；
- 避免图例、刻度和标注互相遮挡；
- 保留脚本和可编辑源文件；
- 在正文中有引用，并且图题简短。

完成后调用 `figure-quality-audit`，检查清晰度、裁切、字体、图例和正文引用。

## 4. 写作和引用

按照比赛模板分章写作，正文中的每个关键数字都能回溯到数据、脚本或结果文件。真实文献通过 `paper-search`、`verifying-bibliography` 和 `reference-manager` 核对；不凭记忆编造作者、题名、期刊、卷期或 DOI。

图表、表格和结论必须来自同一版通过验证的结果。不要为了缩页而把字号、行距或页边距压到模板规范之外。

## 5. 交付前检查

编译最终 PDF 前依次调用：

1. `table-layout-audit`
2. `paper-page-fit`
3. `claim-evidence-audit`
4. `competition-audit`
5. `submission-package-audit`

读取项目配置中的页数口径。发现表格超宽、图片裁切、字体缺失、引用断裂、正文超页或提交目录混入临时文件时，先修复并重新编译。最终报告区分“已确认”“需要修改”和“需要人工确认”，不要把文件存在误报成论文质量合格。

## 6. 过程输出

面向用户的过程说明使用简体中文，保持短句：当前阶段、正在处理的材料、已经产出的文件、下一步和需要复核的风险。不要输出 SDK 内部字段、长命令、英文工具旁白或未经处理的错误栈。
