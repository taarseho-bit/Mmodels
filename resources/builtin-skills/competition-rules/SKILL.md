# 提交合规核验（交卷前最后一道）

只读核验：不改论文、不删文件、不代替用户做提交动作。规则以**当届官方通知为最高依据**——本技能内置的是近年通行的稳定条款，凡当届通知与本文件冲突，以通知为准并把该项标为"待确认（规则版本）"。

## 第一步：确定赛道与当届规则

读项目 `.mathmodel/paper/config.json`（template.id / 语言）与会话上下文判断赛道：`cumcm`（国赛，中文）/ `mcm`、`icm`（美赛）。用户给出了当届通知文件时，先解析通知中的硬性条款（页数、命名、打包），覆盖内置默认值。

## 第二步：逐项核验（输出检查表）

### 国赛 CUMCM 常规条款

| # | 检查项 | 核验方法 |
|---|---|---|
| 1 | **页数上限**：正文（含摘要、图表、附录）不超过当届通知的页数上限 | 数最终 PDF 物理页数（`pdfinfo`/脚本统计），不是数 `\page` 命令 |
| 2 | **承诺书与编号页**：第一页为承诺书、第二页为编号专用页（电子版通常已并入模板首页），且编号页不含队伍信息 | 检查 PDF 前两页文本特征 |
| 3 | **不能出现队号以外的身份信息**：全文（含页眉页脚、PDF 元数据）不得出现学校名/姓名 | 全文 grep 学校/姓名关键词 + `pdfinfo` 查 Author 字段 |
| 4 | **摘要页**：第一页内容页为摘要（承诺书/编号页之后） | 逐页文本抽样 |
| 5 | **支撑材料**：代码、中间结果按通知要求打包（通常一个 zip，命名含队号），不含绝对路径 | 检查打包目录结构与文件名 |
| 6 | 文件命名：论文 PDF 与支撑材料按 `队号`/通知要求命名 | 与通知正则比对 |

### 美赛 MCM/ICM 常规条款

| # | 检查项 | 核验方法 |
|---|---|---|
| 1 | **25 页上限**（近年规则：Summary Sheet + Solution + 参考文献 + 附录 全部计入） | 数 PDF 物理页数 |
| 2 | **Summary Sheet**：第一页为独立摘要页 | 首页文本特征 |
| 3 | **无身份信息**：全文不得出现姓名/学校，PDF 元数据同样检查 | 同国赛 #3 |
| 4 | **AI 使用报告**（近年新增）：按当届要求附 AI 使用说明页（不计入 25 页与否以通知为准） | 检查是否存在且未混入正文页数 |
| 5 | 支撑材料：代码以附录或压缩包形式提交，清单完整可复跑 | 对照 `solve/` 产物清单 |

### 通用技术项

- **PDF 完整性**：能打开、页数与 `\lastpage` 一致、图片全部渲染（无占位框）、字体已嵌入。
- **编译产物一致性**：PDF 修改时间晚于最后一次 `.tex` 修改（防止交了旧稿）。
- **引用真实性**：`book.bib` 条目与正文 `\cite` 一一对应，无引用孤条。

## 第三步：输出

落盘 `submission-check.md`，表格三列（检查项 / 结果 / 证据）：

- **通过**：写证据（如"PDF 共 24 页 ≤ 25"）。
- **违规**：写违规点与修复建议（"第 3 页出现姓名'张三'，见 line 45，需删除"）。
- **待确认**：内置规则覆盖不了、需当届通知或用户确认的项——**没有当届通知时，本技能不得给出"可以提交"的总结论**，只能输出"除 N 项待确认外其余通过"。

最后一段给一句总结论 + 违规项的修复优先级（身份信息 > 页数 > 摘要页 > 命名 > 打包）。
