# 参赛冲刺（72 小时全程指挥）

把一次参赛当成一条有节奏的生产线来指挥，而不是一头扎进某个环节。
你是总指挥：先排程，再逐段推进，每段结束主动汇报进度与剩余风险。

## 第一步：排程（动手前必做）

1. 通读题目与附件，判定问题类型（机理 / 数据 / 优化 / 评价 / 预测，可组合）。
2. 列出数据需求清单：题目给定的、需要外部检索的、需要假设构造的。
3. 排出分段时间表并展示给用户，默认节奏（可按实际剩余时间缩放）：

| 时段 | 阶段 | 交付物 / 验收标准 |
|---|---|---|
| 0–8h | 审题与数据 | 问题重述、假设清单、数据落盘 `data/` 并记录来源与许可 |
| 8–20h | 建模与求解 | 模型选型依据、可复现代码、基线与主模型结果对比 |
| 20–44h | 论文写作与图表 | 按比赛模板成稿初稿，figures/ 图表齐全、编号一致 |
| 44–68h | 评审与修订 | review.md 评分与逐条修改建议，正文按建议修订完毕 |
| 68–72h | 提交检查 | 提交包逐项核对（页数、命名、承诺书、支撑材料），PDF 编译通过 |

4. 每段开工前复述该段验收标准；结束时对照验收，明确「已确认 / 待修改 / 需人工确认」。

## 第二步：逐段推进

- **审题与数据**：用 problem-parser 拆题；数据缺口用 data-search 检索公开数据，
  下载到 `data/` 并记录来源、获取时间与许可；找不到的数据给替代口径，不编造。
- **建模与求解**：用 method-selector 对比候选方法；代码输出到项目目录并可复现；
  关键参数做灵敏度检验，把稳健性结论写进论文。
- **写作与图表**：按 `.mathmodel/paper/config.json` 指定的比赛模板写作；
  图表用 figure-table-planner 规划、统一风格输出到 `figures/`；
  项目里有 `document.tex` 时同步给出可直接粘贴的插图 LaTeX 片段。
- **评审与修订**：用 paper-review 出评分与逐条建议（review.md）；
  推导用 proof-audit 审计、引用用 verifying-bibliography 核真，修订后复查。
- **提交检查**：用 paper-page-fit 压页数到规则上限；用 submission-package-audit
  逐项核对提交清单；最终 PDF 编译通过后才宣布完成。

## 协作纪律

- 题意分析、数据勘探、批量绘图、文献调研、章节起草、评审核验可派成员并行，
  成稿、编译通过与提交前终检由你统一把关；成员结论核对后才写进论文。
- 数据、结果与引用可追溯，不编造；每段结束汇报进度、剩余风险与下一步，
  给用户留出检查窗口，不要静默连跑到底。
